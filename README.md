# 网页锁 · Web Locker

给 Edge 收藏夹里的网页（或整个文件夹）上锁：点开之前必须先输密码。
界面沿用 Smartisan OS 的视觉语言——轻拟物、细描边、灰阶为主、低饱和蓝。

---

## 一、装到 Edge 里（3 步）

1. 打开 Edge，地址栏输入 `edge://extensions/` 回车。
2. 打开左下角的 **「开发人员模式」** 开关。
3. 点顶部的 **「加载解压缩的扩展」**，选中这个文件夹
   （就是包含 `manifest.json` 的那一层，路径：`D:\install\work buddy\web locker`）。

装好后工具栏会出现一个蓝色锁图标。建议点一下拼图图标，把它**固定**到工具栏。

> 这个扩展不联网、不上传任何数据，密码和锁定清单都只存在本机浏览器里。

---

## 二、三步上手

**第 1 步：设密码**
点工具栏的锁图标 → 第一次会让你设一个密码（至少 4 位）。
这个密码之后打开任何被锁的网页、改动任何设置都要用。**忘了只能重装。**

**第 2 步：给网页上锁**
两种方式，随你：

- **从收藏夹挑**：扩展管理页 → 「收藏夹」→ 找到书签，点右边的锁图标 → 选范围 → 上锁。
- **当前网页直接锁**：点工具栏图标 → 「锁定此网页」。

**第 3 步：验证**
点一下那个书签（或在地址栏输入那个网址），会先跳到锁屏页，输密码才进得去。

> **扩展本身也是锁着的**：每次点工具栏图标，第一眼看到的都是密码页，输对了才看得到锁定清单。
> 同一次弹出期间不用重复输；关掉再点开，就要重新输。右上角那个小锁图标可以立刻锁回去。

## 三、四种锁定对象

| 加锁方式 | 拦住的地址 | 适合 |
|---|---|---|
| **整个网站** | 该域名下所有页面（含 `www` 和子域） | 视频站、社交站、网银 |
| **此地址开头** | 以该地址为前缀的页面 | 某个频道的所有分页 |
| **仅这一个地址** | 完全一样的 URL | 单个后台页面 |
| **整个文件夹** | 文件夹里每个书签对应的整站，**且之后新加进去的书签自动纳入** | 「游戏」「工作」这类整理好的文件夹 |

文件夹锁是"活"的：往里面加书签、删书签，保护范围会自动跟着变（靠 `chrome.bookmarks` 事件 + 规则重建）。

### 关于"点开文件夹先弹密码"

**这件事浏览器层面做不到，任何扩展都做不到。** 原因很具体：

- 收藏夹栏是浏览器自己的 UI（属于 chrome 界面，不是网页），扩展没有渲染权；
- `chrome.bookmarks` 只能读写书签数据，书签对象里**没有"隐藏 / 权限 / 可见性"这类字段**；
- 没有任何事件会告诉扩展"用户点开了哪个文件夹"；
- 扩展不能往收藏夹栏或 `chrome://bookmarks` 注入内容脚本——浏览器内部页面禁止注入。

所以"拦截文件夹点击"没有 API 可用。想让别人连书签**看都看不到**，只能换一条路：把书签搬走。

### 文件夹保险箱（隐藏式）

在收藏夹页给文件夹上锁时会问你选哪种：

| 锁法 | 你看到的效果 | 书签在哪 |
|---|---|---|
| **拦截访问** | 文件夹照常展开、书签都在，但点开会跳到密码页 | 原位不动 |
| **隐藏书签** | 文件夹展开后只剩一条「🔒 已上锁 · 点击解锁」 | 搬进「其他收藏夹 → 已上锁」 |

隐藏式的流程：

1. 上锁时把文件夹里的东西**整体移进** `其他收藏夹 / 已上锁 / [原文件夹名]`；
2. 原文件夹放一条替身书签，点它 → 打开锁屏页；
3. 输对密码 → 书签按原顺序搬回原文件夹，替身删掉。

**几个必须知道的事实**：

- 书签是**移走**，不是删除。就算你卸载扩展，它们也还在 `其他收藏夹 → 已上锁` 里，不会丢。
- 这是"藏起来"，不是"加密"。会去翻 `已上锁` 文件夹的人照样能看到内容——它挡的是随手点开的人，不是有心翻找的人。
- 如果开了书签同步，这次搬动会同步到登录同一账号的其他设备。
- 扩展每次启动会自检：万一上次搬到一半浏览器崩了，没登记的书签会被自动搬回原处。

## 四、关于「卸载保护」必须说清楚

你的需求是「卸载也要密码」。**这一条浏览器不允许任何扩展做到**，不是我偷懒：

> Edge / Chrome 的安全模型里，扩展**不能**阻止用户从 `edge://extensions` 页面移除或停用自己。
> 没有这样的 API，也没有绕过它的正当办法——否则任何恶意扩展都能赖在电脑上删不掉。

所以我把它拆成了三层能真正生效的保护：

1. **扩展内部的密码门**（已实现）
   点开图标先要密码；管理页每次打开也要密码（取消验证则整页被遮住，只能看到"已上锁"）。
   所有"减弱保护"的入口——移除锁定项、暂停锁定、改密码、清空数据——同样需要密码。
   别人拿到你的电脑，点开扩展看到的只是一个密码输入框。

2. **配置自毁**（已实现）
   真去扩展管理页点"删除"，浏览器会连带清空扩展的全部存储：锁定清单和密码一起消失。
   重装回来是全新的空扩展，得重新设密码、重新加锁。**删掉 ≠ 解开**，这才是关键。

3. **提示与劝退**（已实现）
   管理页「设置 → 卸载保护」里写明了现状，避免误以为点了删除还能偷偷恢复。

想要真正"删不掉"的效果，只有两条路，都不在扩展的能力范围内：

- 给 Windows 账户设密码，别人根本进不了你的 Edge；
- 或用组策略把 Edge 的扩展安装锁死（需要管理员权限，且不适用于"加载解压缩"的扩展）。

## 五、常见问题

**为什么每次打开扩展都要输密码？**
因为弹出面板里能看到锁定清单、能点"解锁"。不设门的话，任何人点一下图标就把锁解了，前面的功夫全白费。
所以这里用的是"每次打开重新验证"：一次弹出期间验一次就够，关掉即失效。
（输错次数和锁屏页共用同一个计数，连错 5 次一样会锁 60 秒。）

**为什么每次打开都要输密码？**
默认如此，最安全。嫌麻烦可以在「设置 → 解锁后免密」改成 5 / 15 / 30 / 60 分钟内免密
（免密状态只对同一网站生效，关掉浏览器就失效）。

**输错太多次会怎样？**
连续错 5 次，密码框会锁 60 秒（可防别人暴力试密码）。这个计数在关闭浏览器后清零。

**为什么点文件夹不弹密码，而是要把书签搬走？**
因为浏览器不给扩展插手收藏夹栏的机会（见上面「关于点开文件夹先弹密码」）。
`chrome.bookmarks` 没有"隐藏"能力，只有"移到别处"这一条路。

**把书签搬进保险箱，会不会弄丢？**
不会。搬动用的是 `bookmarks.move`，不是删除。就算你把扩展卸了，书签也还在
`其他收藏夹 → 已上锁` 里，随时能手动拖回去。解锁时它们会按原顺序搬回原位。

**密码忘了怎么办？**
没有后门，无法找回。只能：`edge://extensions` 里移除本扩展 → 重新加载 → 重新设密码和加锁。

**会不会把我自己锁在外面？**
锁屏页右下角有「返回上一页 / 关闭此页」，不会困住你。密码对了才进目标网页，密码错了就在锁屏页待着。

**支持 iframe 里的页面吗？**
只拦主框架导航（你主动打开的页面）。网页里嵌的小窗不拦，否则正常网页会被打得稀烂。

**能锁 `chrome://` 或 `edge://` 页面吗？**
不能，也锁不了。浏览器内部页面不允许扩展插手。

**数据存在哪？**
`chrome.storage.local`，密码用 PBKDF2-SHA256（15 万次迭代 + 16 字节随机盐）存哈希，无法还原明文。

## 六、文件结构

```
web locker/
├─ manifest.json          MV3 清单：权限、图标、popup/options 入口
├─ background.js          Service Worker：DNR 规则编译、密码校验、解锁放行
├─ lib/
│  ├─ crypto.js           PBKDF2 口令派生 / 常量时间比对
│  ├─ store.js            本地状态读写（local + session）
│  └─ ui.js               对话框、Toast、favicon 等页面小工具
├─ popup.html/js          点图标弹出的小面板
├─ options.html/js        管理页：锁定清单 / 收藏夹 / 设置
├─ lock.html/js           锁屏页（DNR 重定向到这里）
├─ assets/
│  ├─ smartisan.css       Smartisan OS UI Kit（来样式与 token）
│  ├─ smartisan.js        对话框 / Toast / 滑块的交互helper
│  └─ app.css             本项目补充样式（全部基于上面的 token）
├─ icons/                 16 / 32 / 48 / 128 图标
└─ tools/make_icons.py    图标生成脚本（改了配色可重跑）
```

## 七、技术要点（给自己看的）

- **拦截**：`declarativeNetRequest` 动态规则，`regexFilter` 命中主框架 → `redirect` 到
  `chrome-extension://…/lock.html#<原始URL>`。不用内容脚本，页面不会先闪一下。
- **放行**：验证通过后临时加一条高优先级 `allow` 规则（只对该 origin），`chrome.tabs.update`
  跳回原地址；`webNavigation.onCommitted` 提交后立即回收（开了免密就按时长回收，用 `alarms` 兜底）。
- **锁屏页不留痕迹**：网页模式下不显示域名、完整链接和 favicon，标签页标题固定为「网页已锁定」；
  页面一加载就把 `location.hash`（里面是原始网址）读进 `sessionStorage` 并用 `history.replaceState`
  抹掉，所以地址栏和浏览历史里都看不到目标网址。
- **文件夹锁**：只存 `folderId`，每次重建时用 `chrome.bookmarks.getChildren` 递归展开成多条规则；
  `onCreated / onRemoved / onChanged / onMoved` 触发防抖重建。
- **文件夹保险箱**：`chrome.bookmarks.move` 把子节点整体搬进 `其他收藏夹/已上锁/[id] 名称`，
  原位留一条指向 `lock.html#vault=<id>` 的替身书签；解锁时按 `index` 顺序搬回。
  SW 启动时 `healVault()` 扫描保险箱里没有 lock 认领的文件夹并还原，防止搬运中断留下孤儿数据。
- **权限**：`storage` `bookmarks` `tabs` `declarativeNetRequest` `webNavigation` `alarms` `favicon`，
  外加 `<all_urls>` 主机权限（不这样就没法拦）。

需要改样式时，别直接改 `smartisan.css`，那是有出处的原文件；把改动写进 `assets/app.css`。
